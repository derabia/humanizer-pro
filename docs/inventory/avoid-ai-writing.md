## 4. Tiered vocabulary table

**Structure** (`references/patterns.md:35–213`): the tier names are **Tier 1**
(split into **1A** and **1B**), **Tier 2**, **Tier 3** (words), and
**Tier 3 phrases**. There is no separate "Tier 4."

| Tier | Meaning | Weighting rule | Detector weight |
|---|---|---|---|
| Tier 1A — AI frequency markers | "Words claimed to appear far more often in machine text than in human writing. A cluster of these is evidence about how a passage was produced." ## 5. Modes — exact workflow steps and output contract (quoted)

`SKILL.md` defines three modes (§105–126):

### `rewrite` (default)

> "1. **Audit it**: identify every justified AI-ism present, citing the specific text
> 2. **Rewrite it**: make the authorized, applicable edits while retaining protected findings and source-blocked gaps for the final report
> 3. **Summarize when useful**: briefly list meaningful changes when edits were made; omit the summary for a no-op" (`SKILL.md:131–133`)

Plus an **automatic marks pass**: normalize quotes/apostrophes via
`node scripts/normalize-quotes.js <rewritten-prose> --reference <original> --write`
run from the installed skill directory, against a scratch file containing only
the changed editable paragraphs (`SKILL.md:135`).

**Output format — rewrite mode** (`SKILL.md:220–244`, quoted structure):
- **Final rewrite** — "Return the full rewritten content exactly once... Never publish a first-pass draft and then supersede it with another full version."
- **Changes** (optional) — "when a short summary is useful"
- **Verification** — four explicit items: **Editing passes** (used and limit), **Checks** (executed, model-only, or unavailable), **Residuals** (findings left and why, or none found), **Stop reason** (no further justified in-scope edit, requested limit reached, or unresolved verification failure). "A pass count alone is not a stop reason." (`SKILL.md:234`)
- Optional **Issues found** section (before Final rewrite) only "If the user explicitly requests a detailed or exhaustive audit" (`SKILL.md:240`).

### `detect`

> "1. **Audit it**: identify every justified AI-ism present, citing the specific text
> 2. **Assess it**: note which flags are clear problems vs. patterns that may be intentional or effective in context" (`SKILL.md:139–140`)

**Output format — detect mode** (`SKILL.md:246–256`, quoted):
> "**1. Issues found** — A bulleted list of every justified AI-ism identified, with the offending text quoted. Group by severity (P0, P1, P2). Keep Tier 1B clarity edits visually separate from Tier 1A markers...
> **2. Assessment** — For each flag, note whether it's a clear problem or a judgment call... If the text is clean, say so."
>
> "State whether the detector actually ran or the audit was model-only... Report zero editing passes; detect mode performs no marks normalization or rewriting."

### `edit`

> "1. **Read** the file the writer named
> 2. **Edit in place**: apply minimal, targeted fixes to the justified, authorized spans with the Edit tool, leaving already-human passages untouched
> 3. **Verify**: re-read the file, report what changed, and identify any intentional, protected, source-blocked, pass-limit, or verification residual" (`SKILL.md:144–146`)

Refuses source code, configuration, and generated data files (`SKILL.md:117`).

**Output format — edit mode** (`SKILL.md:258–276`, quoted):
> "**1. Edits made** — A bulleted list of the changes, each with the file location and the before → after. Only the spans you touched.
> **2. Verification** — Confirm you re-read the file and state whether any further justified in-scope edit remains..."
>
> **Mechanical check** (optional, recommended): `node detector/validate.js <original> <rewritten>`. "It exits non-zero when a rewrite altered a fenced code block, YAML frontmatter, a blockquote, a table cell, inline code, a URL, a file path, or the heading structure, and when the rewrite introduced more flagged patterns than it removed."

**Mode-selection trigger phrases** (`SKILL.md:119`): "detect," "flag only,"
"audit only," "just flag," "scan," "what AI patterns are in this" → detect
mode; naming a file + asking to fix/clean it in place → edit mode; otherwise
default rewrite.

**Invocation options** (`SKILL.md:121`): `[--mode rewrite|detect|edit]`,
`[--voice casual|professional|technical|warm|blunt]`,
`[--context linkedin|blog|technical-blog|investor-email|docs|casual]`,
`[--file PATH]`, `[--iterate 1|2]`, `[--style CONFIG|GUIDE]`.

**Iterate to convergence** (`SKILL.md:123–125`): "A normal rewrite may use up
to two editing passes: the initial rewrite and, only when review finds
another justified in-scope edit, one corrective pass." `--iterate 1` caps at
one pass; `--iterate 2` (or "iterate"/"keep going until it's clean") uses the
same two-pass default ceiling.

## 6. Two-pass audit procedure (quoted)

There is no separately named "two-pass audit" section; the mechanism is the
**iterate-to-convergence** editing-pass budget described in `SKILL.md:123–125`
and enforced through the output-format rules in `SKILL.md:220–244`:

> "One editing pass is one stage that changes the returned text or named file.
> An explicit voice, structure, or mechanics transformation belongs to that
> pass. Marks normalization planned as part of the rewrite belongs to the
> same pass; a later change prompted by a check uses the next pass. Audits,
> re-reading, detector rechecks, and preservation checks do not consume an
> editing pass. A no-op uses none. A corrective edit and a preservation
> repair share the requested budget: once its limit is reached, report any
> residual or verification failure instead of changing the text again.
> Report the number of editing passes used and why the workflow stopped."
> (`SKILL.md:125`)

Procedure, quoted from `SKILL.md:226–228`:

> "Before delivery, compare the final text with the source. Account for each
> changed span: it must address a justified finding or belong to an
> explicitly requested transformation... If review finds an unauthorized
> change, repair it only within the remaining editing budget; otherwise
> report the unresolved failure."
>
> "Check an explicit transformation against the entire editable final text
> before calling it complete... Plan these changes together within the
> requested editing pass."

The repo's evaluated automated-gate report (`evals/rewrite/reports/
automated-stack-295-296-2026-09-16/README.md`) validates exactly this
mechanism against live model runs — see §11.

## 7. Voice profiles (verbatim, `references/patterns.md:690–711`)

> "Context profiles (above) set *how strict* to be for an audience. Voice
> profiles set *how the prose should sound* — the persona. They're
> independent axes... Voice is **optional** — if the writer doesn't name one,
> infer it from the input's existing register and don't impose a persona on
> text that already has one."

Five named profiles, each "a set of concrete targets, not a vibe":

> **`casual`** — "When explicitly requested, prefer contractions and direct,
> conversational sentences; do not force fragments or a sentence-length
> quota. When inferred, preserve the source's existing casual markers rather
> than intensifying them... *Blog posts, social, community.*"
>
> **`professional`** — "Prefer active voice when the actor matters. Vary
> accidental repetition without enforcing a sentence-length quota... *LinkedIn,
> investor email, sponsor pitches.*"
>
> **`technical`** — "Prefer plain copulatives ('X is Y') over inflated
> substitutes ('serves as,' 'stands as a testament to')... *Docs, technical
> blog.*"
>
> **`warm`** — "Address the reader directly where the source already speaks to
> them ('you'), and keep its acknowledgment rather than adding one... *Mentorship,
> onboarding, thank-yous.*"
>
> **`blunt`** — "Lead with the claim; cut 'It's important to note that'
> windups. Em-dashes are rare here... *Decision memos, thought leadership, hard
> feedback.*"

> "**Calibrate to a sample (optional).** If the writer gives you a sample of
> their own writing... analyze its sentence-length pattern, contraction rate,
> paragraph openings, and recurring word choices, then match those instead of
> a named profile."

> "**How voice composes with context.** Apply context and each rule's pass
> conditions first. An inferred voice does not reactivate a category the
> context skips... When applicable voice and context rules set numeric
> thresholds for the same feature, use the stricter threshold... Sensible
> default pairings remain casual↔casual, professional↔linkedin/investor-email,
> and technical↔docs/technical-blog."

Context profiles (distinct axis, `patterns.md:608–685`): `linkedin`, `blog`
(default), `technical-blog`, `investor-email`, `docs`, `casual`, each mapped
to a detector `contextMode` (`marketing`, `general`, `technical`, `marketing`,
`technical`, `personal` respectively) via the table at `patterns.md:625–634`.
Full **tolerance matrix** (25 rules × 6 profiles, `patterns.md:640–665`) sets
per-rule strictness (`strict` / `relaxed` / `skip` / `extra strict`) per
profile — e.g. em dashes are `skip` under `casual` but `strict` under `blog`;
hashtag stuffing is `extra strict` under `investor-email`.

## 8. Detector engine (`detector/patterns.js`)

- **Entry file**: `detector/patterns.js` (2906 lines). Zero-dependency IIFE
  (`const AIDetector = (() => {...})()`), runs identically under Node ≥18 and
  browser `<script>` (self-registers as global `AIDetector`;
  `module.exports` guarded by `typeof module !== 'undefined'`,
  `patterns.js:2904–2906`).
- **Exported API** (`patterns.js:2891–2899`):
  ```js
  return {
    analyzeText,   // (text, options?) => result
    normalizeText, // bypass-trick normalizer, exposed for reuse
    getLabel,      // (score:0-100) => string
    getColor,      // (score:0-100) => hex string, for UI
    SEVERITY_LABELS, // {critical:'P0', high:'P1', medium:'P2', low:'P3'}
    TYPE_LABELS,   // 53-entry map of detector `type` -> human label
  };
  ```
- **`analyzeText(text, options)` signature** (`patterns.js:1679`):
  `options.contextMode` ∈ `{general (default), technical, marketing,
  personal}`; unknown values fall back to `general` with
  `stats.contextModeFallback` set (`patterns.js:1700–1703`).
  `options.sourceMode` ∈ `{plain (default), rendered-markdown}`; the latter
  masks initial YAML frontmatter and HTML comments before scoring
  (`patterns.js:1709–1720`).

### Pipeline (in call order, `patterns.js:1679–2549`)

1. Empty-text short-circuit → `label: 'Empty'`.
2. Build `sourceMap` (identity array mapping working-string code units back
   to source code units) so all later offset-changing passes stay reversible
   (`identitySourceMap`, `patterns.js:54–56`).
3. Rendered-markdown masking (frontmatter + HTML comments) if
   `sourceMode==='rendered-markdown'` (`maskRenderedMarkdown`).
4. Blockquote masking/stripping (≥2 consecutive `> ` lines) so quoted text
   isn't scored against the quoting author (`stripMultilineBlockquotes` /
   `maskMultilineBlockquotes`).
5. Bypass-trick normalization (`normalizeText`): strips zero-width chars,
   Cyrillic/Greek homoglyph lookalikes (`CYRILLIC_LOOKALIKES`,
   `GREEK_LOOKALIKES`, `patterns.js:39–45`), and roleplay asterisk markers;
   tracks counts in `norm.flags` for later corroboration.
6. **Unsegmented-script gate**: if CJK (Han/Hiragana/Katakana) characters are
   ≥50% of non-space chars, return `label: 'Unsupported script'`, unscored
   (`patterns.js:1743–1767`). Hangul (Korean) is excluded — it's
   space-separated and scores normally.
7. **Length gates**: `wordCount < 10` → `'Too short'`; `wordCount > MAX_WORDS`
   (`MAX_WORDS = 10000`, `patterns.js:1654`) → `'Text too long'`. Both
   unscored (`score:0`, `document_classification:'UNSCORED'`).
8. Tokenize, split paragraphs/sentences.
9. **Tier 1 words** (single-token `TIER1` lookup) + **Tier 1 phrases**
   (`TIER1_PHRASES`, each entry has `.clarity` boolean splitting `tier1` vs
   `tier1-clarity`) — deduped per distinct lowercased match
   (`patterns.js:1795–1830`).
10. **Tier 2 clusters**: per-paragraph token scan; a paragraph issues `tier2`
    for every found word only when ≥2 distinct Tier-2 words co-occur in that
    paragraph (`patterns.js:1832–1863`).
11. **Tier 3 density**: `densityThreshold = max(3, floor(wordCount*0.03))`;
    flags a canonical Tier-3 word only once its paragraph-independent count
    across the whole document meets that threshold (`patterns.js:1866–1886`).
12. ~40 additional regex/structural pattern categories run via
    `matchPatterns(text, REGEX_ARRAY, type, severity)`
    (`patterns.js:1889–2450`), each backed by a literal regex-array constant
    (e.g. `TRANSITIONS`, `CHATBOT_ARTIFACTS`, `SYCOPHANTIC`, `FILLERS`,
    `GENERIC_CONCLUSIONS`, `LETS_PATTERNS`, `REASONING_ARTIFACTS`,
    `SIGNIFICANCE_INFLATION`, `VAGUE_ATTRIBUTIONS`, `HOLLOW_INTENSIFIERS`,
    `EMOTIONAL_FLATLINE`, etc. — full list mirrors `TYPE_LABELS`, §below).
13. **Bold overuse**: `>3` `**bold**` spans → `formatting` issue
    (`patterns.js:2441–2450`).
14. **Dedup**: `deduplicateIssues` keys on `${type}:${text.toLowerCase()}`
    (`patterns.js:2818–2826`).
15. **Scoring** (`patterns.js:2452–2467`, quoted from the file's own header
    comment, lines 11–25):
    > "Each category has a weight in the `ISSUE_WEIGHTS` table. Detection
    > runs produce raw (possibly duplicate) issues which are then
    > deduplicated by (type, text) pair. `rawScore` is the sum of category
    > weights across the deduped list... `rawScore` is then normalized to
    > 0-100 via `log2(wordCount/50)` so longer texts don't accumulate
    > unboundedly on the same density of patterns."

    Exact formula:
    ```js
    rawScore += ISSUE_WEIGHTS[issue.type] ?? 2;      // per deduped issue
    const lengthFactor = Math.max(1, Math.log2(wordCount / 50));
    const normalizedScore = Math.min(100, Math.round(rawScore / lengthFactor));
    ```
16. **Label** (`getLabel`, `patterns.js:2801–2808`):
    `score===0→'Clean'`; `≤15→'Minimal AI signals'`; `≤35→'Some AI
    patterns'`; `≤60→'Moderate AI signals'`; `≤80→'Strong AI signals'`;
    else `'Heavy AI patterns'`.
17. **Sentence-region highlighting** (`buildSentenceRegions`,
    `patterns.js:2598–2703`): coarse `.!?`-terminated sentence spans;
    per-sentence hit count/weight from non-style-only issue types
    (`NON_HIGHLIGHT_TYPES` excludes `punct-distribution`,
    `cross-para-burstiness`, `fnword-trigram-entropy`,
    `smart-punct-signature`, `normalization-flag`, `uniformity`, `em-dash`,
    `formatting`, `tier3`, `tier3-phrase`, `tier3-phrase-cluster`,
    `hashtag-stuff`, `bullet-np-list`, `unnecessary-hyphenation`, and any
    type whose `ISSUE_WEIGHTS` entry is 0); contiguous flagged sentences are
    window-merged allowing a 1-sentence gap; each region's `score = min(1,
    weight/20)`.
18. **Trinary classification** (`classifyTrinary`, `patterns.js:2723–2799`,
    "GPTZero-shaped," explicitly FN-biased — quoted: "biases the detector to
    prefer making less-harmful false-negative errors over false-positive
    errors"):
    - **Strong corroborators** (each near-dispositive): `cutoff-disclaimer`
      present; `normalization-flag` ≥2 (zero-width or homoglyph hits);
      `reasoning-artifact` **and** `chatbot` co-occurring; `denseAIVocab`
      (`wordCount≥150 AND tier1Distinct≥5 AND tier2Clusters≥2 AND
      hasTransition`).
    - **Weak corroborators**: ≥2 of `{punct-distribution,
      cross-para-burstiness, fnword-trigram-entropy}`; or
      `smart-punct-signature` alone.
    - **Classification thresholds**: `score<15 AND strongCorrob===0 →
      HUMAN_ONLY`; `strongCorrob≥1 OR score≥70 → AI_ONLY`; `score≥40 AND
      totalCorrob≥1 → AI_ONLY`; else `MIXED`.
    - **Confidence**: `high` if `strongCorrob≥2 OR hasCutoff OR (score<8 AND
      wordCount≥100)`; `medium` if `strongCorrob≥1 OR (score≥45 AND
      weakCorrob≥1) OR score<20`; else `low`.
    - **Class probabilities**: soft `aiSoft = min(0.97, score/100 +
      totalCorrob*0.06 + strongCorrob*0.08)`; distributed to
      `{human, mixed, ai}` by classification-specific formulas, then
      renormalized so the three sum to exactly 1.0 (`ai` assigned as the
      remainder to avoid floating drift).

## 9. Preservation validator (`detector/validate.js`)

- **Entry file**: `detector/validate.js` (495 lines), same IIFE +
  `module.exports` shape as `patterns.js` so it also loads in a browser.
- **Purpose** (quoted, `validate.js:1–8`): "SKILL.md promises that a rewrite
  leaves certain things alone... Nothing enforced those promises. This does."
- **Exported API**: `{ validate, formatResult, maskCode, extractIndentedBlocks }`.
- **`validate(original, rewritten, options?)` signature**:
  - `options.detector` — an `AIDetector` instance (defaults to
    `require('./patterns.js')` when available).
  - `options.skipResidual` — skip the "patterns must not grow" check.
  - `options.maxShrinkRatio` — warn threshold for word-count shrinkage
    (default `0.4`, i.e. warn past a 40% drop).
  - Returns `{ ok, errors[], warnings[], stats }`, where
    `stats = { wordsBefore, wordsAfter, fencedBlocks, headings,
    indentedBlocks, residual }`.
- **CLI usage**: `node detector/validate.js <original-file> <rewritten-file>`
  — exits 1 on any error, 0 on pass; prints `formatResult()` (`PASS —
  preservation checks clear` or `FAIL — N preservation error(s)` with per-item
  `error`/`warning` lines).
- **Checks performed** (every check listed with its error/warning code):

  | Code | Level | Check |
  |---|---|---|
  | `code-block-count` | error | Fenced code block count changed |
  | `code-block-modified` | error | A fenced code block's exact content changed |
  | `frontmatter-modified` | error | YAML frontmatter added/removed/changed |
  | `blockquote-modified` | error | Blockquote content modified or removed |
  | `table-modified` | error | Markdown table content modified or removed |
  | `inline-code-missing` | error | Inline code span(s) removed |
  | `url-missing` | error | URL removed or altered (compared with AI tracking params stripped from both sides) |
  | `path-missing` | error | Filesystem path removed or altered |
  | `heading-count` | error | Heading count changed |
  | `heading-level` | error | Heading nesting (h1..h6) changed |
  | `heading-text` | warning | Heading wording changed (expected for Title Case/emoji fixes) |
  | `number-missing` | warning | A figure present in the original is absent from the rewrite |
  | `large-shrink` | warning | Rewrite dropped more than `maxShrinkRatio` (default 40%) of words |
  | `residual-grew` | error | `after.issues.length > before.issues.length` — rewrite introduced new detector-flagged patterns |

- **Documented carve-outs** (`validate.js:18–29`): (1) AI-tool URL tracking
  parameters (`utm_source=chatgpt.com` and friends, matched by
  `AI_URL_PARAM` regex) are stripped from both sides before URL comparison,
  because SKILL.md instructs stripping them; (2) heading *text* changes are
  warning-level only (SKILL.md instructs Title-Case/emoji heading fixes),
  while heading *count/nesting* changes remain errors.
- **Fence-span algorithm**: a plain line-scanner (`fenceSpans`,
  `validate.js:51–79`), not a regex, because "regex can't express run lengths
  reliably" for nested/mismatched ``` / ~~~ fences — mirrors
  `fenceRanges()` in `patterns.js` so both report the same boundaries.
- **Table extraction**: GFM tables with or without outer pipes, requiring a
  delimiter row (`extractTableBlocks`, `validate.js:203–217`), escaped-pipe
  aware (`tableCells`, `validate.js:169–190`).
- **Indented code blocks**: counted but not error-enforced — "four-space
  indentation is also how markdown continues a list item, and a validator
  that blocks a legitimate rewrite is worse than one that reports a soft
  signal" (`validate.js:238–244`).
- **CRLF normalization**: both inputs are normalized to `\n` up front so
  Windows-authored documents don't hide protected content from the
  regex-anchored extractors (`validate.js:319–327`).
- **Exit codes** (CLI): `0` pass, `1` preservation error present. (No `2` code
  in `validate.js` itself; usage errors without both file args also exit `2`
  per `validate.js:485–487`.)

## 13. Punctuation rules (exact quotes)

**Em dashes** (`references/patterns.md:10`):
> "**Em dashes (— and --)**: Replace with commas, periods, parentheses, or
> rewrite as two sentences. Target: zero. Hard max: one per 1,000 words. This
> applies to headings and section titles too, not just body prose. Catch both
> the Unicode em dash (—) and the double-hyphen substitute (--)."

Carve-out, same line: a list-item em dash after a bolded lead term or markdown
link (`- **Term** — description`) "is typography, not a prose splice — don't
count it toward the rate." Detector weight is **0** (style-only, no
authorship-score effect) per `patterns.js:388` because "usage has varied by
model generation and vendor, so do not score or invert it as an authorship
signal" (`SKILL.md:182`).

**Curly quotation marks and apostrophes** (`patterns.md:14`):
> "Curly quotes and apostrophes (U+201C/U+201D, U+2018/U+2019) are a *weak*
> paste-from-chat signal — meaningful mainly in plain-text contexts like code
> comments, commit messages, or plaintext drafts, where nothing auto-curls.
> Treat as corroborating, never conclusive: Word, Google Docs, macOS, and iOS
> curl quotes by default, so most human prose contains them too. Don't flag
> curly apostrophes (U+2019) on their own. Replace with straight quotes in
> plain-text/code; leave them in finished publications and locale-correct
> punctuation (French « », German „ ")."

Detector: `smart-punct-signature` fires **only** when curly quotes co-occur
with an em-dash, an Oxford comma, and clean typing (≥80 words) — "never on
curly punctuation alone" (`detector/CATEGORIES.md:72–77`), weight **6**.

**No dedicated en-dash rule.** `references/patterns.md` and `detector/
patterns.js` do not treat the en dash (–) as a distinct pattern; the only
en-dash mention found is inside the "deeply" Tier-2 carve-out example text and
range-notation prose, not as a detection rule.

**Normalization mechanics** (`SKILL.md:135`, marks pass): quotes/apostrophes
are normalized in editable prose only via `scripts/normalize-quotes.js`,
inferred independently per quote family — "majority wins, ties use the first
observed style, and no evidence leaves that family unchanged." An explicit
house-style setting overrides inference: `--quotes straight` or `--quotes
curly`.

## 14. Formatting rules (exact quotes)

**Bullets** (`patterns.md:13`):
> "**Excessive bullet lists**: Flag bullet-heavy sections whose content is not
> genuinely list-like. Convert them to prose only when the user's scope
> permits restructuring; otherwise report the structural problem. Feature
> comparisons, step-by-step instructions, and API parameters stay as lists."

Related, "Excessive structure" (`patterns.md:519–520`):
> "Too many headers in short text: more than 3 headings in under 300 words can
> signal unnecessary scaffolding... Too many list items: review 8+ bullet
> points in under 200 words when the material is not genuinely list-shaped."

Detector: `bullet-np-list` (weight 10) fires on "A list of 5+ consecutive
bullet items where each item is a short (≤6 word) adjective-plus-noun phrase
with no verb" (`patterns.md:282`).

**Bold** (`patterns.md:11`):
> "**Bold overuse**: Strip bold from most phrases. One bolded phrase per major
> section at most, or none. If something's important enough to bold,
> restructure the sentence to lead with it instead."

Detector rule (`patterns.js:2441–2450`): `boldMatches = text.match(/\*\*[^*]+\*\*/g)`;
fires `formatting` issue when `boldMatches.length > 3`.

**Headings** (`patterns.md:359–360`, Title case headings):
> "AI over-capitalizes headings: 'Strategic Negotiations And Key Partnerships'
> instead of 'Strategic negotiations and key partnerships.' Use sentence case
> for subheadings. Title case only for the piece's main title, if at all."

Detector: `title-case-header` (weight 4), suppressed in `technical`
`contextMode` (skips title-case headers per `detector/README.md:126`).

**Emoji in headers** (`patterns.md:12`):
> "Remove entirely. No `## 🚀 What This Means`. Exception: social posts may use
> one or two emoji sparingly — at the end of a line, never mid-sentence."

## 16. Surprises / discrepancies vs. stated expectations

Expected: "Three modes (detect / rewrite / edit), two-pass audit, tiered
vocabulary table, voice profiles, deterministic JS detector (0–100 score),
preservation validator, structured output format."

All seven expected components exist and match, with these refinements/
surprises worth flagging:

1. **"Two-pass audit" is actually a two-pass *editing* budget, not an audit
   step.** There is no separately named "audit pass 1 / audit pass 2"
   procedure. Audits, re-reads, detector reruns, and preservation checks are
   explicitly **free** ("do not consume an editing pass," `SKILL.md:125`) —
   only text-changing stages count against the 2-pass ceiling. `--iterate 1`
   and `--iterate 2` cap *editing* passes, not audit passes.
2. **The detector is not a single monolithic score — it's a dual system.**
   Beyond the 0–100 `score`/`label`, the engine also emits a full GPTZero-
   shaped **trinary classifier** (`HUMAN_ONLY`/`MIXED`/`AI_ONLY` +
   `class_probabilities` + `confidence_category`) layered on top, deliberately
   FN-biased. This is a materially richer surface than "a 0–100 score."
3. **Three pattern-category counts coexist on purpose** (74 README / 112+10
   vocabulary / 53 detector types / 90 distinct named `###` entries by this
   inventory's own count) and the project explicitly warns against
   reconciling them — a naive "how many patterns" question has no single
   correct answer.
4. **A meaningful fraction of the catalog is explicitly *not* detector-
   detectable and is documented as such**, including two patterns that were
   *built as detectors and then deliberately reverted* (`acknowledgment
   loops` #239, `narrated candor`, and `wall-of-text replies`) because the
   regex could not separate the AI tell from legitimate idiomatic English —
   this is unusually candid engineering history for a "detector" project.
5. **Several weight-0 categories exist in the scoring table by design**
   (`em-dash`, `emotional-flatline`, `unnecessary-hyphenation`) — they appear
   in `issues[]` and are shown to the user, but are mathematically inert for
   scoring/classification purposes. This is a deliberate "visible but
   non-scoring" tier not implied by the task's framing of "0–100 score."
6. **Voice profiles and context profiles are explicitly two independent
   axes**, not one "audience/tone" setting — "you can write blunt for a blog
   or warm for docs." The task description's phrasing ("voice profiles")
   undersells that there's also a *separate*, larger context-profile
   tolerance matrix (6 profiles × 25 rules) governing rule strictness.
7. **The project ships a self-measured false-positive/accuracy research
   program** (hash-only human-control corpus, HC3/RAID machine corpus,
   `fp-measure.js`/`fp-compare.js`/`fp-preprocess.js`, `corpus/manifest.json`)
   — this goes well beyond "a detector with a preservation validator" and
   wasn't implied by the stated expectations at all. The gate's default
   threshold of 6 findings/file is derived from this measurement (1.9% vs.
   31.4% human-corpus false-positive rate), not chosen arbitrarily.
8. **The repository is a multi-skill network, not a single skill.** Beyond
   the canonical `avoid-ai-writing` skill, there are 6 more thin
   "companion" skills (`avoid-ai-writing-router`, `ai-writing-detector`,
   `voice-preserving-rewriter`, `file-edit-in-place`, `preservation-verifier`,
   `false-positive-reviewer`) plus a machine-readable typed skill graph
   (`skill-graph.json`) with `ROUTE`/`FEED`/`VERIFY`/`REPAIR` edges — built
   specifically for the ChatGPT/Codex plugin submission, per `OPENAI_PLUGIN.md`
   and `NOTICE.md` (contributed by a named external contributor, Mamdouh
   Aboammar, not the primary author).
9. **The repo dogfoods its own detector against its own docs** (`PROOF.md`,
   `scripts/self-scan.js`) and publishes both the flattering ("exemption-aware")
   and unflattering (raw) scores side by side, explicitly framed as: "publishing
   only the flattering one is the behavior this project exists to criticize."
10. **The rewrite-preservation evaluation for the most recent stack (PRs
    #295/#296) currently reports a FAIL**, not a clean pass — a live model
    (`opencode/mimo-v2.5-free`) claimed to have made an edit it did not
    actually make on the "protected content" scenario, and the stack remains
    unmerged pending issue #322. This is recent, live evidence that the
    output-contract claims (accurate Verification/Changes reporting) are an
    active, only-partially-solved problem, not a settled property of the
    skill.
11. **No `dependencies`/`devDependencies` in `package.json` at all** — the
    entire test suite (20 suites, 466 assertions) ran cleanly with zero `npm
    install`, confirming the "zero-dependency, build-step-free" claim in
    `detector/README.md` is accurate down to the test harness itself, not
    just the shipped detector.
