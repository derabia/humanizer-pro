# Coverage map

Every pattern ID declared in `references/` (EN-*, AR-SH-*, AR-MSA-*, AR-EGT-*,
AR-SHM-*), matched against how (or whether) `scripts/lib/` actually checks it.
Three classes:

- **lexicon**: a compiled regex/word-list pattern in
  `scripts/lib/ar-detector/lexicons.js` (`RAW_PATTERNS`, checked by ID) or the
  tier tables `scripts/lib/en-detector/index.js` matches directly
  (`en-vocabulary.md`, not ID-addressed; see the note under the EN table).
- **signal**: a stylometric or structural check in
  `scripts/lib/ar-detector/signals.js` or a named `type`/`category` string in
  `scripts/lib/en-detector/index.js`, cited by comment or engine category name
  rather than by pattern ID (the English engine does not tag issues with
  `EN-NNN` IDs; the mapping below is this project’s own correlation between
  category name and catalog entry, not a literal ID lookup).
- **judgment-only**: no compiled check. The pattern is applied by reading the
  reference entry and judging the text against it; `detect`/`rewrite`/`edit`
  still cite the pattern ID in the report, but no script flags it
  automatically. Default when unsure, per the owner instruction for this pass.

Generated by reading each reference file’s own `## `/`### ` headings against
`scripts/lib/ar-detector/lexicons.js` (`RAW_PATTERNS`, exported for docs/tests)
and `scripts/lib/ar-detector/signals.js` (checked by comment reference), plus
`scripts/lib/en-detector/index.js`’s named pattern-group categories cross-read
against `docs/inventory/avoid-ai-writing.md` §8’s `TYPE_LABELS` discussion.
This file was produced by a one-off generation script for this round and is
kept current going forward by `tests/coverage-map.test.js`, which fails the
build rather than regenerating the file automatically.
