# Conflicts between upstream sources

Scope: conflicts found between `blader/humanizer` (BL), `avoid-ai-writing` (AW),
and `humanizer-semitic` (SM: SM-MSA / SM-EGT / SM-SHM), and between the three
Arabic varieties inside `humanizer-semitic` itself. Every row cites
`repo/file:line` for each side. Precedence levels use the planned order given
in the task (1 highest): 1 Protected content, 2 Explicit user instruction,
3 User voice sample, 4 Selected voice profile, 5 Language/dialect reference
(incl. native typography), 6 Shared core patterns.

Ids in this file (`C-01…`) are provisional research ids, not final merged
rule ids.

## Non-conflicts checked

Candidates from the task brief that were checked against the sources and did
**not** turn out to be real conflicts:

- **Bold-as-decoration / decorative headings.** blader BL-019/BL-020
  (`blader/SKILL.md:277-303`), avoid-ai-writing's Bold overuse and Title case
  headings (`avoid-ai-writing/references/patterns.md:11,359-360`), and
  semitic MSA's Markdown Overuse (`_sources/semitic/skills/humanizer-ar-msa/SKILL.md:275-286`)
  all converge on the same position: strip bold used as decoration, use
  sentence case, no dedicated carve-out disagreement between any pair. Not a
  conflict — folds cleanly into one shared-core rule (see DEDUP-MAP.draft.md).
- **Curly quotes are "weak alone."** blader §21 (`blader/SKILL.md:292-297`,
  "Most editors auto-curl, so this is weak alone") and avoid-ai-writing's
  curly-quote rule (`avoid-ai-writing/references/patterns.md:14`, "a *weak*
  paste-from-chat signal... corroborating, never conclusive") state the same
  position in different words. No conflict on *strength*; the only real issue
  is the Arabic-typography coverage gap already captured as C-03.
- **Chatbot residue / chatbot artifacts severity ranking.** blader calls §22
  "the most certain tell in this list" with no carve-out
  (`blader/SKILL.md:307-309`); avoid-ai-writing tags the equivalent rule
  `chatbot`, P0, weight 8 — one of the highest weights in the table
  (`avoid-ai-writing/references/patterns.md:318-320`,
  `avoid-ai-writing/detector/patterns.js` weight table). Both rank it at or
  near the top of their respective severity schemes. Not a conflict.
- **"Not X but Y" contrast.** blader BL-001 (`blader/SKILL.md:58-74`) and
  avoid-ai-writing's split-sentence/tailing-negation rule AW-007
  (`avoid-ai-writing/references/patterns.md:18`) describe the same
  construction with compatible fixes (state the point directly; keep a
  contrast only when both halves carry information). This is a **dedup**
  candidate, not a conflict — see DEDUP-MAP.draft.md.
- **Hashtag stuffing / significance inflation / vague attribution severity.**
  blader's Section C is not internally tiered but is introduced as high-value
  ("The fact underneath is usually sound," `blader/SKILL.md:196`);
  avoid-ai-writing tags the equivalent rules P0 (`significance-inflation`,
  `vague-attribution`, `hashtag-stuff`, `avoid-ai-writing/references/patterns.md:239-241,275-279,305-306`).
  Directionally consistent (both treat these as high-priority), so not listed
  as a conflict beyond the general taxonomy note in C-09/C-14.

Gaps confirmed by direct search rather than assumed:

- No en-dash rule exists in any of the three upstreams (blader treats en
  dashes identically to em dashes inside its single dash rule,
  `blader/SKILL.md:161`; avoid-ai-writing has no en-dash-specific pattern at
  all per the inventory; semitic never mentions en dashes).
- No Arabic punctuation (، ؛ ؟, « ») or Arabic-Indic-digit rule exists
  anywhere in `_sources/semitic` (confirmed by `grep` across all three Arabic
  `SKILL.md` files for the glyphs and for "curly"/"smart quote" — see C-03).
